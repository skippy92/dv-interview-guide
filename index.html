PROJECT-01 Production UVM Scoreboard DSP FIR Filter
Self-Checking UVM Scoreboard with Fixed-Point Q8 Math & ±1 LSB Tolerance Margin
▼
Architectural Principle & Floating vs. Fixed-Point Trap

Digital Signal Processing (DSP) filters process continuous data streams using fixed-point arithmetic (such as Q8 or Q1.7) to minimize silicon area and latency. Fixed-point representation truncates or rounds continuous mathematical calculations to a discrete bit width ($N=8$ fractional bits, step size $2^{-8} = 0.00390625$).

When verifying an $N$-tap FIR filter ($Y[n] = \sum_{k=0}^{N-1} h[k] \cdot X[n-k]$), floating-point models in the testbench evaluate continuous precision numbers, causing false-positive comparison mismatches against RTL output. The verification scoreboard must replicate fixed-point saturation and quantization arithmetic bit-for-bit while enforcing a programmable $\pm 1\text{ LSB}$ tolerance window to absorb hardware rounding-mode divergencies.

dsp_fir_scoreboard.sv 
`uvm_analysis_imp_decl(_axis_in)
`uvm_analysis_imp_decl(_axis_out)

class dsp_fir_scoreboard #(int NUM_TAPS = 8, int DATA_WIDTH = 16) extends uvm_scoreboard;
  `uvm_component_param_utils(dsp_fir_scoreboard#(NUM_TAPS, DATA_WIDTH))

  // Analysis Imps for Ingress and Egress streaming ports
  uvm_analysis_imp_axis_in  #(axis_seq_item, dsp_fir_scoreboard#(NUM_TAPS, DATA_WIDTH)) in_imp;
  uvm_analysis_imp_axis_out #(axis_seq_item, dsp_fir_scoreboard#(NUM_TAPS, DATA_WIDTH)) out_imp;

  // Software Shift Register modeling the physical delay-line
  protected int signed delay_line[$];
  
  // Mirrored filter coefficients in Q8 format (loaded via RAL or shadow registers)
  int signed coeff_table[NUM_TAPS];

  // Expected transaction queue
  protected int signed expected_output_q[$];

  // Verification metrics
  int match_count;
  int mismatch_count;
  int lsb_tolerance_hits;

  function new(string name = "dsp_fir_scoreboard", uvm_component parent = null);
    super.new(name, parent);
    in_imp  = new("in_imp", this);
    out_imp = new("out_imp", this);
  endfunction

  virtual function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    // Initialize delay line with zeros
    for (int i = 0; i < NUM_TAPS; i++) begin
      delay_line.push_back(0);
      coeff_table[i] = (1 << 7); // Default unity coefficients (1.0 in Q8)
    end
  endfunction

  // Ingress Write: Evaluates fixed-point convolution upon every valid beat
  virtual function void write_axis_in(axis_seq_item tx);
    int signed new_sample;
    int signed accumulator = 0;
    int signed q8_result;

    new_sample = int'(signed'(tx.tdata[DATA_WIDTH-1:0]));

    // Push new sample into delay line and discard oldest tap
    delay_line.push_front(new_sample);
    void'(delay_line.pop_back());

    // Compute Convolution: Y[n] = Sum(h[k] * X[n-k])
    for (int k = 0; k < NUM_TAPS; k++) begin
      accumulator += (coeff_table[k] * delay_line[k]);
    end

    // Scale down from Q8 intermediate multiplication: (Q8 * Q8) >> 8
    q8_result = accumulator >>> 8;

    // Fixed-Point Saturation Logic to prevent wrap-around
    if (q8_result > 32767)       q8_result = 32767;
    else if (q8_result < -32768) q8_result = -32768;

    expected_output_q.push_back(q8_result);
  endfunction

  // Egress Write: Pops expected sample and evaluates tolerance
  virtual function void write_axis_out(axis_seq_item tx);
    int signed actual_sample;
    int signed expected_sample;
    int signed diff;

    if (expected_output_q.size() == 0) begin
      `uvm_error("SCOREBOARD_UNEXPECTED", "Received output packet with no expected data available!")
      return;
    end

    actual_sample   = int'(signed'(tx.tdata[DATA_WIDTH-1:0]));
    expected_sample = expected_output_q.pop_front();
    diff            = actual_sample - expected_sample;

    // Evaluate against strict +/- 1 LSB quantization window
    if (diff == 0) begin
      match_count++;
      `uvm_info("SB_EXACT_MATCH", $sformatf("Exact Match: 0x%04h", actual_sample), UVM_HIGH)
    end else if (diff == 1 || diff == -1) begin
      lsb_tolerance_hits++;
      `uvm_info("SB_TOLERANCE_MATCH", $sformatf("Sample matched within +/-1 LSB (Diff = %0d)", diff), UVM_MEDIUM)
    end else begin
      mismatch_count++;
      `uvm_error("SB_MISMATCH", $sformatf("Arithmetic Mismatch! Actual=0x%04h, Expected=0x%04h, Delta=%0d", 
                                          actual_sample, expected_sample, diff))
    end
  endfunction

  virtual function void check_phase(uvm_phase phase);
    super.check_phase(phase);
    if (expected_output_q.size() != 0) begin
      `uvm_error("SB_DRAIN_LEAK", $sformatf("Simulation ended with %0d unprocessed expected samples!", 
                                            expected_output_q.size()))
    end
    `uvm_info("SB_SUMMARY", $sformatf("Matches: %0d | LSB Tolerance Hits: %0d | Mismatches: %0d", 
                                      match_count, lsb_tolerance_hits, mismatch_count), UVM_NONE)
  endfunction
endclass
PROJECT-02 RAL & Sequence Coordination DSP Dynamic Reload
Concurrent AXI4-Lite Dynamic Coefficient Reloading with Shadow Register Strobe
▼
Verification Challenge: Hitless Mode Switching

In high-speed DSP IPs, coefficients must be updated at runtime without stalling or corrupting in-flight streaming traffic. Hardware designs use shadow register banks: firmware writes new tap values to temporary staging registers, then pulses a COEFF_UPDATE_STROBE bit. On the next stream packet boundary (or TLAST assertion), the hardware atomically swaps the active tap bank with the shadow bank.

dsp_reload_seq.sv 
class dsp_dynamic_reload_seq extends uvm_sequence;
  `uvm_object_utils(dsp_dynamic_reload_seq)

  dsp_reg_block regmodel;
  rand bit [15:0] new_coeffs[8];

  // Ensure filter stability by constraining coefficient sum
  constraint c_stability {
    foreach (new_coeffs[i]) {
      new_coeffs[i] inside {[16'h0010 : 16'h00FF]};
    }
  }

  task body();
    uvm_status_e status;
    uvm_reg_data_t read_data;

    `uvm_info("RELOAD_SEQ", "Starting Dynamic Coefficient Reload via RAL...", UVM_LOW)

    // 1. Stage new coefficients into Shadow Registers via AXI-Lite Frontdoor
    for (int i = 0; i < 8; i++) begin
      regmodel.shadow_coeff[i].write(status, new_coeffs[i], UVM_FRONTDOOR, .parent(this));
      if (status != UVM_IS_OK)
        `uvm_fatal("RAL_WRITE_FAIL", $sformatf("Failed writing shadow coeff[%0d]", i))
    end

    // 2. Poll Status to ensure DSP pipeline is active
    regmodel.ctrl_stat.read(status, read_data, UVM_FRONTDOOR, .parent(this));
    `uvm_info("DSP_STATUS", $sformatf("DSP Status before strobe = 0x%08h", read_data), UVM_HIGH)

    // 3. Issue atomic commit strobe: write 1 to COMMIT bit [0]
    regmodel.coeff_strobe.write(status, 32'h1, UVM_FRONTDOOR, .parent(this));

    // 4. Verify strobe bit self-clears once hardware completes swap
    do begin
      #20ns;
      regmodel.coeff_strobe.read(status, read_data, UVM_FRONTDOOR, .parent(this));
    end while (read_data[0] == 1'b1);

    `uvm_info("RELOAD_SEQ", "Coefficient reload successfully committed into active DSP datapath!", UVM_LOW)
  endtask
endclass
PROJECT-03 RTL & SVA Checkers Multi-Clock FIFO
Complete Parameterized Asynchronous FIFO RTL with Dual-Clock Gray Pointer Continuity SVA
▼
CDC Theory & Pointer Wrap Mechanics

An asynchronous FIFO bridges asynchronous clock domains using dual-port RAM. To prevent metastability from corrupting pointer comparison, write and read pointers are converted to Gray code ($P_{\text{gray}} = P_{\text{bin}} \oplus (P_{\text{bin}} \gg 1)$) before passing through 2-stage synchronizers. Pointer bit-width must be $N+1$ for depth $2^N$ to distinguish full and empty states.

async_fifo.sv (RTL + Formal Assertions) 
module async_fifo #(
  parameter int DATA_WIDTH = 32,
  parameter int ADDR_WIDTH = 4 // Depth = 2^4 = 16 locations
)(
  // Write Domain
  input  logic                  wr_clk,
  input  logic                  wr_rst_n,
  input  logic                  wr_en,
  input  logic [DATA_WIDTH-1:0] wr_data,
  output logic                  fifo_full,

  // Read Domain
  input  logic                  rd_clk,
  input  logic                  rd_rst_n,
  input  logic                  rd_en,
  output logic [DATA_WIDTH-1:0] rd_data,
  output logic                  fifo_empty
);

  localparam int DEPTH = 1 << ADDR_WIDTH;

  // Dual-Port RAM
  logic [DATA_WIDTH-1:0] mem [DEPTH-1:0];

  // Binary and Gray Pointers
  logic [ADDR_WIDTH:0] wptr_bin, wptr_gray;
  logic [ADDR_WIDTH:0] rptr_bin, rptr_gray;

  // Synchronizers
  logic [ADDR_WIDTH:0] rptr_gray_sync1, rptr_gray_sync2;
  logic [ADDR_WIDTH:0] wptr_gray_sync1, wptr_gray_sync2;

  // -------------------------------------------------------------
  // Write Domain Datapath
  // -------------------------------------------------------------
  always_ff @(posedge wr_clk or negedge wr_rst_n) begin
    if (!wr_rst_n) begin
      wptr_bin  <= '0;
      wptr_gray <= '0;
    end else if (wr_en && !fifo_full) begin
      mem[wptr_bin[ADDR_WIDTH-1:0]] <= wr_data;
      wptr_bin  <= wptr_bin + 1'b1;
      wptr_gray <= ((wptr_bin + 1'b1) >> 1) ^ (wptr_bin + 1'b1);
    end
  end

  // Synchronize Read Pointer into Write Domain (2-Flop)
  always_ff @(posedge wr_clk or negedge wr_rst_n) begin
    if (!wr_rst_n) begin
      rptr_gray_sync1 <= '0;
      rptr_gray_sync2 <= '0;
    end else begin
      rptr_gray_sync1 <= rptr_gray;
      rptr_gray_sync2 <= rptr_gray_sync1;
    end
  end

  // Full condition: MSB inverted, second MSB inverted, lower bits identical
  assign fifo_full = (wptr_gray == {~rptr_gray_sync2[ADDR_WIDTH:ADDR_WIDTH-1], 
                                     rptr_gray_sync2[ADDR_WIDTH-2:0]});

  // -------------------------------------------------------------
  // Read Domain Datapath
  // -------------------------------------------------------------
  always_ff @(posedge rd_clk or negedge rd_rst_n) begin
    if (!rd_rst_n) begin
      rptr_bin  <= '0;
      rptr_gray <= '0;
      rd_data   <= '0;
    end else if (rd_en && !fifo_empty) begin
      rd_data   <= mem[rptr_bin[ADDR_WIDTH-1:0]];
      rptr_bin  <= rptr_bin + 1'b1;
      rptr_gray <= ((rptr_bin + 1'b1) >> 1) ^ (rptr_bin + 1'b1);
    end
  end

  // Synchronize Write Pointer into Read Domain (2-Flop)
  always_ff @(posedge rd_clk or negedge rd_rst_n) begin
    if (!rd_rst_n) begin
      wptr_gray_sync1 <= '0;
      wptr_gray_sync2 <= '0;
    end else begin
      wptr_gray_sync1 <= wptr_gray;
      wptr_gray_sync2 <= wptr_gray_sync1;
    end
  end

  // Empty condition: Synchronized Gray write pointer equals Gray read pointer
  assign fifo_empty = (rptr_gray == wptr_gray_sync2);

  // -------------------------------------------------------------
  // CONCURRENT SYSTEMVERILOG ASSERTIONS (SVA)
  // -------------------------------------------------------------
  // Property: Gray pointer must NEVER jump by more than 1 bit per cycle
  property p_wptr_gray_continuity;
    @(posedge wr_clk) disable iff (!wr_rst_n)
    $changed(wptr_gray) |-> $onehot(wptr_gray ^ $past(wptr_gray));
  endproperty
  a_wptr_gray: assert property (p_wptr_gray_continuity)
    else $error("CDC FATAL: Write Gray pointer changed by more than 1 bit!");

  property p_rptr_gray_continuity;
    @(posedge rd_clk) disable iff (!rd_rst_n)
    $changed(rptr_gray) |-> $onehot(rptr_gray ^ $past(rptr_gray));
  endproperty
  a_rptr_gray: assert property (p_rptr_gray_continuity)
    else $error("CDC FATAL: Read Gray pointer changed by more than 1 bit!");

  // Property: No Overflow
  property p_no_overflow;
    @(posedge wr_clk) disable iff (!wr_rst_n)
    fifo_full |-> !wr_en;
  endproperty
  a_overflow: assert property (p_no_overflow)
    else $error("FIFO OVERFLOW: wr_en asserted while fifo_full is HIGH!");

  // Property: No Underflow
  property p_no_underflow;
    @(posedge rd_clk) disable iff (!rd_rst_n)
    fifo_empty |-> !rd_en;
  endproperty
  a_underflow: assert property (p_no_underflow)
    else $error("FIFO UNDERFLOW: rd_en asserted while fifo_empty is HIGH!");

endmodule
PROJECT-04 RTL Bug Reproduction Suite Intel Security IP

RTL Bug Mechanics: Defective Lock Flop

During security IP validation at Intel, a critical flaw was root-caused in a 32-bit write-once register[cite: 2]. A write of 1 was specified to permanently lock configuration bits [3:0] until hardware reset. However, if software executed an initial housekeeping write of 0, all subsequent writes of 1 were discarded.

The defective RTL sampled the write strobe directly: reg_locked <= 1'b1 asserted on any write strobe, locking the register into a 0 state! To prove root cause to the design owner, a test suite of 4 per-bit directed testcases was developed.

#!/usr/bin/env python3
"""
Automated Nightly Regression Log Parser and Bug Classifier
Categorizes simulation failures across compute farm disks.
"""

import os
import re
import sys
from pathlib import Path
from collections import defaultdict

SIGNATURE_RULES = {
    "SVA_ASSERTION": re.compile(r"\*Error\*\s+Assertion\s+([A-Za-z0-9_]+)\s+failed"),
    "UVM_FATAL":     re.compile(r"UVM_FATAL\s+([A-Za-z0-9_/\.-]+)\s*:\s*(.*)"),
    "SB_MISMATCH":   re.compile(r"UVM_ERROR.*\[(SB_[A-Za-z0-9_]+)\].*Mismatch!"),
    "TIMEOUT_HANG":  re.compile(r"Fatal:\s+Watchdog\s+timer\s+expired\s+after\s+(\d+\w+)"),
    "NULL_POINTER":  re.compile(r"Null\s+pointer\s+dereference.*handle\s+is\s+null"),
    "DECERR_SLVERR": re.compile(r"AXI_PROTOCOL_VIOLATION.*(DECERR|SLVERR)")
}

def triage_logs(log_directory: str):
    buckets = defaultdict(list)
    total_logs = 0
    passed = 0

    log_files = list(Path(log_directory).rglob("*.log"))
    total_logs = len(log_files)

    print(f"[+] Found {total_logs} simulation logs in {log_directory}. Triaging...")

    for log_path in log_files:
        with open(log_path, 'r', encoding='utf-8', errors='ignore') as f:
            content = f.read()

        if "TEST PASSED" in content and "UVM_ERROR :    0" in content:
            passed += 1
            continue

        matched = False
        for signature_type, regex in SIGNATURE_RULES.items():
            match = regex.search(content)
            if match:
                signature_id = f"{signature_type}::{match.group(1)}"
                buckets[signature_id].append(str(log_path.name))
                matched = True
                break

        if not matched:
            buckets["UNCATEGORIZED_FAILURES"].append(str(log_path.name))

    # Print Executive Summary Report
    print("\n" + "="*80)
    print(f"REGRESSION TRIAGE SUMMARY: {passed}/{total_logs} Passed ({(passed/total_logs)*100:.1f}%)")
    print("="*80)
    
    for sig, test_list in sorted(buckets.items(), key=lambda x: len(x[1]), reverse=True):
        print(f"\n[SIGNATURE] {sig} -> Count: {len(test_list)}")
        for test_name in test_list[:3]:
            print(f"   |-- {test_name}")
        if len(test_list) > 3:
            print(f"   |-- ... and {len(test_list)-3} more tests.")

if __name__ == "__main__":
    dir_to_scan = sys.argv[1] if len(sys.argv) > 1 else "./sim_logs"
    triage_logs(dir_to_scan)

Q01 Data Types Simulation Trap
Fundamental Difference Between 2-State and 4-State Data Types in SV
▼
Data Representation & Host CPU Packing

SystemVerilog categorizes data types into two distinct memory modeling domains:

  • 2-State Types (bit, byte, shortint, int, longint): Represent only 0 and 1; default value is strictly 0[cite: 1]. Simulators pack 64 2-state bits into a single 64-bit CPU register word, facilitating parallel SIMD vector instructions, drastically reducing host RAM footprint, and accelerating simulation speed[cite: 1].
  • 4-State Types (logic, integer, time, reg, wire): Represent 0, 1, X (unknown/contention), and Z (high-impedance); default value is X (except wire, which defaults to Z)[cite: 1]. Under the hood, simulators represent each bit using two machine words: an aval (value) word and a bval (mask) word[cite: 1]. This doubles the memory footprint and adds branching overhead during bitwise operations[cite: 1].
⚠️ Industrial Verification Trap: Reset & X-Masking Bug

Connecting a 2-state bit variable to an uninitialized or reset-floating DUT interface wire silently coerces RTL X states into clean 0s[cite: 1]. This masks reset synchronization bugs, floating bus lines, and uninitialized control registers during gate-level or RTL simulation[cite: 1]. Golden Rule: Always use 4-state logic on pin interfaces and clocking blocks[cite: 1].

Q06 Subprograms Arguments

▼

▼

Task: Can consume simulation time (using #delay, @(posedge clk), or wait())[cite: 1]. Tasks can call other tasks and functions[cite: 1]. They do not return values via direct assignment syntax (must use output or ref arguments)[cite: 1].

Q08 Memory Lifetimes

▼

Q65 Phase Hazards Objection Deadlock

Q101 AMBA AXI4 Architecture
Decoupled 5-Channel Architecture of AMBA AXI4
▼
Channel Independence & Full-Duplex Bandwidth

AXI4 defines five completely independent, unidirectional transaction channels:

  • Write Address Channel (AW): Transmits target write destination address, burst length (AWLEN), burst size (AWSIZE), burst type (AWBURST), cache attributes, and security credentials.
  • Write Data Channel (W): Carries write payload beats along with byte-lane qualifiers (WSTRB) and end-of-burst flags (WLAST)[cite: 1].
  • Write Response Channel (B): Returns transaction completion status (OKAY, EXOKAY, SLVERR, DECERR) from the target slave or interconnect endpoint[cite: 1].
  • Read Address Channel (AR): Carries target read address and burst control parameters[cite: 1].
  • Read Data Channel (R): Streams read payload beats alongside transaction completion status (RRESP) and the final beat indicator (RLAST)[cite: 1].

Decoupling Advantage: Read and write datapaths operate completely full-duplex and out-of-order[cite: 1]. Because address and data paths are separate, an AXI master can issue write address requests dozens of cycles ahead of write data transmission or simultaneously issue read bursts without bus turnaround dead-time[cite: 1].

Q102 AMBA AXI4 Handshake Rules
Fundamental VALID/READY Handshake Rules
▼

A data/control transfer occurs strictly on the rising clock edge where both VALID and READY are sampled HIGH[cite: 1].

  • Rule 1 (Transmitter Independence): The source (transmitter) must never wait for READY to assert before asserting VALID[cite: 1]. Once VALID asserts, it must remain HIGH until the handshake completes[cite: 1].
  • Rule 2 (Receiver Flexibility): The destination (receiver) is permitted to wait for VALID to assert before asserting READY, or it can speculatively assert READY beforehand[cite: 1].
  • Rule 3 (Payload Stability): Once VALID is asserted, the associated address, data, and sideband control lines must remain completely stable until the active cycle where READY is sampled HIGH[cite: 1].
Deadlock Trap: Cyclic Handshake Dependencies

If Master A waits for READY=1 before driving VALID=1, while Slave B waits for VALID=1 before driving READY=1, the bus enters a permanent deadlock state. AXI VIP monitors must flag any master delaying VALID based on READY as a fatal protocol breach.

Q103 AMBA AXI4 Dependencies
AXI4 Write Handshake Dependencies
▼
  • AWREADY can assert independently or wait for AWVALID[cite: 1].
  • WREADY can assert independently or wait for WVALID[cite: 1].
  • Critical Decoupling: WVALID is permitted to assert before AWVALID[cite: 1]. A write data burst can legally begin transmission before the write address phase completes[cite: 1].
  • BVALID (Write Response) must wait for both the write address handshake (AWVALID & AWREADY) and the final write data beat handshake (WVALID & WREADY & WLAST) to complete before asserting[cite: 1].
  • BREADY can wait for BVALID, or assert beforehand[cite: 1].
Q104 AMBA AXI4 Dependencies
AXI4 Read Handshake Dependencies
▼
  • ARREADY can assert independently or wait for ARVALID[cite: 1].
  • RVALID (Read Data) must strictly wait for the read address handshake (ARVALID & ARREADY) to complete before asserting[cite: 1]. A slave can never return speculative read data before accepting the address[cite: 1].
  • RREADY can wait for RVALID or assert speculatively prior to RVALID[cite: 1].
Q105 AXI4 Trap Address Alignment
The 4KB Address Boundary Crossing Rule
▼

The Rule: In AMBA AXI4, a single continuous burst transfer must never cross a 4KB address boundary (i.e., address bits [11:0] wrapping from 0xFFF to 0x000)[cite: 1].

Architectural Reason: Interconnect address decoders and Memory Management Units (MMUs) allocate address decoding at 4KB memory page boundaries[cite: 1]. If a burst crossed 4KB, intermediate beats could cross into a completely different physical slave peripheral without re-arbitrating or decoding the new destination address[cite: 1].

Verification Duty: Master sequences must implement automated address-splitting logic[cite: 1]. If a randomized burst length and start address calculate an envelope crossing 4KB, the sequence must split the transaction into two separate AXI transactions[cite: 1]. A concurrent SVA property must flag any single burst crossing 4KB as an immediate protocol violation[cite: 1].

Q106 AMBA AXI4 Burst Modes
Burst Types: FIXED vs. INCR vs. WRAP
▼
Burst Type AxBURST Address Calculation Behavior Primary Application
FIXED 2'b00[cite: 1] Target address remains identical for every beat in the burst[cite: 1]. Reading or writing memory-mapped FIFO peripherals (e.g., UART/SPI FIFO registers)[cite: 1].
INCR 2'b01[cite: 1] Address increments linearly by transfer size (2^AxSIZE) for each beat[cite: 1]. Standard sequential bulk memory access (DDR DRAM, SRAM, DMA streaming)[cite: 1].

Q107 Whiteboard Calculation WRAP Burst
WRAP Burst Boundary Calculation Mechanics
▼

Rules: WRAP burst length must be 2, 4, 8, or 16 beats, and the start address must be aligned to the transfer size[cite: 1].

Total_Bytes   = Number_of_Beats * (2^AxSIZE)[cite: 1]
Wrap_Boundary = (Start_Address / Total_Bytes) * Total_Bytes[cite: 1]
Upper_Limit   = Wrap_Boundary + Total_Bytes[cite: 1]
Worked Example

Start Address = 0x04, AxLEN = 3 (4 beats), AxSIZE = 2 (4 bytes)[cite: 1]:

  • Total Bytes = $4 \times 4 = 16\text{ bytes (0x10)}$[cite: 1]
  • Wrap Boundary = $(0\text{x}04 / 16) \times 16 = \mathbf{0\text{x}00}$[cite: 1]
  • Upper Limit = $0\text{x}00 + 0\text{x}10 = \mathbf{0\text{x}10}$[cite: 1]
  • Generated Beat Addresses: 0x04 → 0x08 → 0x0C → (wraps to boundary) 0x00[cite: 1]
Q108 AMBA AXI4 Encoding
Burst Length (AxLEN) and Burst Size (AxSIZE) Encoding
▼
  • AxLEN[7:0]: Specifies number of data transfers (beats)[cite: 1]. The actual number of beats is AxLEN + 1[cite: 1]. Range: 1 to 256 beats for INCR; 1 to 16 beats for FIXED and WRAP[cite: 1].
  • AxSIZE[2:0]: Specifies maximum bytes transferred in each beat: 3'b000 = 1 Byte, 3'b001 = 2 Bytes, 3'b010 = 4 Bytes, 3'b011 = 8 Bytes, 3'b100 = 16 Bytes ... up to 3'b111 = 128 Bytes[cite: 1]. Rule: AxSIZE can never exceed the physical bus datapath width[cite: 1].
Q109 AMBA AXI4 Byte Strobes
WSTRB (Write Strobes) and Narrow Transfers
▼

Each bit of WSTRB[N-1:0] qualifies one byte lane on the write data bus ($N = \text{Data Width} / 8$)[cite: 1]. A byte is committed to memory only if its corresponding WSTRB[n] bit is 1'b1[cite: 1].

Narrow Transfers: When an AXI master issues a transfer where AxSIZE is smaller than the physical data bus width (e.g., 32-bit transfer on a 64-bit bus)[cite: 1]. The active byte lanes shift on each beat depending on address alignment[cite: 1]:

  • Beat 1 (Addr 0x00): WSTRB = 8'b0000_1111 (Lower 4 bytes active)[cite: 1]
  • Beat 2 (Addr 0x04): WSTRB = 8'b1111_0000 (Upper 4 bytes active)[cite: 1]
Q110 AMBA AXI4 Signaling
WLAST and RLAST Signaling Rules
▼
  • WLAST: Asserted HIGH by the write master strictly during the final data beat of a write burst[cite: 1]. A slave must use WLAST to confirm all burst beats have arrived before returning the write response (BVALID)[cite: 1].
  • RLAST: Asserted HIGH by the read slave strictly during the final data beat of a read burst[cite: 1].
  • Bug Trap: Any mismatch between the burst beat count defined by AxLEN and the assertion of WLAST/RLAST causes slave state machine hang-ups[cite: 1].

Q112 AMBA AXI4 Reset Verification
Reset Rules in AXI4 (ARESETn)
▼
  • ARESETn is active-LOW[cite: 1]. It may assert asynchronously, but deassertion must be synchronized to the rising edge of ACLK[cite: 1].
  • During reset, masters must drive AWVALID, WVALID, and ARVALID to 1'b0[cite: 1].
  • During reset, slaves must drive BVALID and RVALID to 1'b0[cite: 1].
  • All other signals can be unknown (X), though driving them stable is recommended[cite: 1]. VALID signals can assert at the earliest on the rising clock edge immediately following ARESETn deassertion to 1'b1[cite: 1].
Q113 AMBA AXI4 Out-of-Order
Out-of-Order (OoO) Completion and AXI IDs
▼

AXI4 uses transaction identification tags (AWID, BID, ARID, RID) to allow out-of-order execution across disparate slaves[cite: 1]:

  • Identical IDs: Transactions issued with the same ID tag must be returned in strict chronological order[cite: 1].
  • Different IDs: Transactions with different IDs have no ordering restrictions[cite: 1]. A fast peripheral (internal SRAM) can return read data for ARID=2 before a high-latency external memory (DDR) finishes returning data for ARID=1[cite: 1].
Q114 AMBA AXI3 vs AXI4 Interleaving
Why was Write Data Interleaving (WID) Removed in AXI4?
▼

In AXI3, write data beats from different write transactions could be interleaved on the W channel using the WID signal[cite: 1]. This required complicated reassembly buffers and reordering logic in slave endpoints[cite: 1].

AXI4 completely removed WID and eliminated write interleaving[cite: 1]. In AXI4, all write data beats for transaction A must be transmitted contiguously until WLAST=1 before write data beats for transaction B can begin, simplifying interconnect routing and slave buffers[cite: 1].

Q115 Performance DV Outstanding Queues
Outstanding Transactions and Interconnect Capacity
▼

An outstanding transaction is an address request that has been accepted by the slave/interconnect (address handshake complete), but whose final response (BVALID or RLAST) has not yet returned[cite: 1].

Interconnect Capacity: Defines the maximum number of in-flight address tracking slots in the interconnect buffers[cite: 1]. Verification testbenches must stress tests up to this ceiling, validating backpressure handling and stall logic when outstanding buffers saturate[cite: 1].

If a 32-bit transfer starts at unaligned address 0x01 on a 32-bit (4-byte) bus[cite: 1]:

  • Subsequent Beats: The burst automatically aligns to the container boundary (0x04, 0x08, etc.) with WSTRB = 4'b1111[cite: 1].

Q119 AMBA AXI4 Write Ordering

▼
  • Same AWID: A slave must commit writes to physical memory and return write responses (BVALID) in the exact chronological order the write address handshakes occurred[cite: 1].

  • Different ARID: Read data bursts can be returned in any order[cite: 1]. Furthermore, read beats of burst A (RID=1) can interleave with read beats of burst B (RID=2)[cite: 1].
Q121 Hazard Verification RAW Hazard
RAW (Read-After-Write) Hazards Across Different IDs
▼

If an AXI master issues a write to address 0x1000 with AWID=1, and immediately issues a read to address 0x1000 with ARID=2, the AXI4 specification does not guarantee ordering between different channels or IDs[cite: 1].

The read might overtake the write in the interconnect routing fabric, returning stale data[cite: 1]. To prevent RAW hazards, the master must wait for the write response (BVALID) for AWID=1 before asserting ARVALID for ARID=2, or utilize an interconnect equipped with address hazard tracking logic[cite: 1].

Coordinates clock-gating and power-down sequences between clock controllers and peripherals[cite: 1]:

  2. Peripheral completes in-flight transactions, drains internal FIFOs, and asserts CSYSACK = 0 to confirm readiness[cite: 1].

  4. Wake-up: Controller drives CSYSREQ = 1; peripheral powers up and acknowledges with CSYSACK = 1[cite: 1].
Q123 AXI4-Lite Architecture
AXI4-Lite Architecture and Simplifications
▼

AXI4-Lite is a stripped-down subset of AXI4 optimized for memory-mapped Control and Status Registers (CSRs)[cite: 1]:

  • All bursts are fixed to a length of 1 beat (no AxLEN signal)[cite: 1].
  • Data bus width is fixed to 32-bit or 64-bit (no narrow transfers)[cite: 1].
  • No AXI ID tags: All transactions complete in strict chronological order[cite: 1].
  • No cache attributes (AxCACHE) or atomic locks (AxLOCK)[cite: 1].
Q124 AXI4-Lite Architecture
Why Does AXI4-Lite Forbid Burst Transfers?
▼

AXI4-Lite is designed strictly for reading and writing memory-mapped control and status registers[cite: 1]. Register accesses do not benefit from multi-beat streaming bursts[cite: 1]. Removing burst counters, wrap calculation logic, and narrow lane shifting significantly reduces gate count and logic complexity in peripheral slaves[cite: 1].

Q125 AXI4-Stream Data Streaming

  • Transfers are continuous and unbounded; a transfer can range from a single sample to an infinite byte stream[cite: 1].

Q141 CDC Fundamentals Metastability
Metastability and Setup/Hold Violations in CDC
▼

When an asynchronous signal transitions within the setup ($t_{\text{su}}$) or hold ($t_h$) timing window of a destination flip-flop, the flop's internal bistable feedback circuit cannot resolve to a definitive logic 0 or 1 within the expected propagation delay[cite: 1].

The output enters a metastable state—hovering at an intermediate voltage level or oscillating—before eventually settling randomly to 0 or 1[cite: 1]. If sampled by downstream logic, this causes catastrophic state machine corruption[cite: 1].

Q142 CDC Fundamentals MTBF Equation
MTBF (Mean Time Between Failures) Mathematical Formulation
▼
MTBF = 1 / Failure_Rate = exp(s * t_r) / (T_0 * f_clk * f_data)[cite: 1]
  • f_clk: Frequency of receiving clock domain[cite: 1].
  • f_data: Frequency of incoming asynchronous data transitions[cite: 1].
  • t_r: Resolution time available for the synchronizer to settle before the next clock edge[cite: 1].
  • T_0, s: Process parameters of the CMOS flip-flop technology[cite: 1].

Increasing synchronizer flip-flop stages increases settling time $t_r$, boosting MTBF exponentially[cite: 1].

Q143 CDC Circuits Synchronizers
2-Flop vs. 3-Flop Synchronizer Architecture
▼
  • 2-Flop Synchronizer: Two flip-flops in series clocked by the destination clock[cite: 1]. The first flop absorbs potential metastability; the second flop samples the settled output, providing a clean logic level[cite: 1].
  • 3-Flop Synchronizer: Adds an extra flop stage to provide an additional clock cycle of resolution time[cite: 1]. Standard requirement in deep submicron nodes (< 7nm) or high-frequency designs (> 1GHz) where MTBF is reduced[cite: 1].
  • Restriction: Synchronizers are strictly valid for 1-bit control signals[cite: 1]. Multi-bit buses must never use parallel synchronizers[cite: 1].
Q144 CDC Hazards Bus Skew
Why Parallel Multi-Bit Signals Must Never Use 2-Flop Synchronizers
▼

Physical routing delays introduce bus skew between individual wires of a multi-bit bus[cite: 1].

If a value transitions from 2'b01 to 2'b10, skew can cause the destination synchronizers to sample bit 0 early and bit 1 late[cite: 1]. The receiving domain samples the transient intermediate value 2'b11 or 2'b00 for one clock cycle, corrupting the transfer[cite: 1]. Solution: Use multi-bit handshake protocols (Req/Ack) or Gray-coded Asynchronous FIFOs[cite: 1].

Q145 FIFO Architecture CDC
Asynchronous FIFO Architecture
▼

A dual-clock FIFO decouples asynchronous write (wr_clk) and read (rd_clk) domains[cite: 1]:

  • Write Pointer (wptr): Converted to Gray code and synchronized into rd_clk domain via 2-flop synchronizer[cite: 1].
  • Read Pointer (rptr): Converted to Gray code and synchronized into wr_clk domain via 2-flop synchronizer[cite: 1].
  • Status Flags: FIFO Full is generated in wr_clk domain; FIFO Empty is generated in rd_clk domain[cite: 1].
Q146 Gray Coding FIFO Pointers
Why Gray Code is Mandatory for FIFO Pointer Synchronization
▼

Gray code ensures that exactly one bit changes value per count increment[cite: 1].

In standard binary counting, transitioning from 3 (011) to 4 (100) flips all 3 bits simultaneously[cite: 1]. Due to routing skew, destination synchronizers might sample intermediate values (e.g., 000, 010), causing pointer jumps[cite: 1]. With Gray code, because only one bit changes, the receiving synchronizer samples either the old pointer or the new pointer—neither outcome corrupts FIFO state[cite: 1].

▼

Q151 SVA Core Assertion Types
Immediate vs. Deferred Immediate vs. Concurrent Assertions
▼
Execution Semantics & Glitch Filtering
  • Simple Immediate Assertions (assert (condition)): Evaluated procedurally within the Active scheduling region like an if condition. Highly vulnerable to intermediate simulation glitches in combinational logic when inputs oscillate before settling within a delta cycle.
  • Deferred Immediate Assertions (assert #0 (condition) / assert final (condition)): Evaluated procedurally in the Active region, but their pass/fail reporting is deferred until the Observed (for #0) or Postponed (for final) region. This completely filters out transient combinational glitches while retaining procedural execution semantics.
  • Concurrent Assertions (assert property (...)): Clock-driven, temporal checks evaluated over single or multi-cycle time windows[cite: 1]. They sample values in the Pre-poned region, evaluate property expressions in the Observed region, and trigger pass/fail action blocks in the Reactive region[cite: 1].
Q152 SVA Core IEEE Scheduler
SVA Scheduling: Pre-poned, Observed, and Reactive Regions
▼
  1. Pre-poned Region: Signal values and sampled value functions (such as $past and $rose) are sampled right before the active clock edge, reading stable values settled in the previous time step before any current-cycle RTL evaluations occur[cite: 1].
  2. Observed Region: Property expressions, sequences, and temporal implication operators (|->, |=>) are evaluated using the stable values captured during the Pre-poned region[cite: 1].
  3. Reactive Region: Pass/fail action blocks (e.g., $error, `uvm_error) execute, and UVM testbench stimulus driving from clocking blocks is processed[cite: 1].
Q153 SVA Architecture Directives
SVA Hierarchy: Sequence vs. Property vs. Assertion Directives
▼

  • Property (property...endproperty): A higher-level temporal rule that wraps sequences with clocking events, implication operators (|->, |=>), and disable reset conditions (disable iff)[cite: 1].

Q154 SVA Core Implication
Overlapping (|->) vs. Non-Overlapping (|=>) Implication
▼

Q155 SVA Trap Vacuous Success
Vacuous Success: Mechanism, Risks, and Prevention
▼

Mechanism: In an implication property (A |-> B), if antecedent A evaluates to false, the property passes automatically without ever evaluating consequent B[cite: 1]. This is designated as a vacuous pass[cite: 1].

Verification Risk: If a simulation bug causes antecedent condition A to never assert (for instance, if req is stuck at 0 due to an agent configuration error), the assertion report displays a 100% passing rate, creating a false sense of verification closure while masking critical RTL bugs[cite: 1].

Prevention: Author companion cover properties (cover property (A ##0 B);) to verify that the antecedent condition triggers in simulation[cite: 1]. Additionally, run simulators with command-line flags (such as Synopsys VCS -assert vacuous=no) to suppress vacuous successes in regression reports[cite: 1].

Q201 Security DV Intel Project
32-Bit Write-Once Security Register Architecture & Lock Mechanics
▼
Architectural Principle

In hardware security modules (HSMs) and Root-of-Trust (RoT) controllers, write-once registers prevent untrusted runtime firmware from altering privileged cryptographic policies or boot fuses after ROM boot execution[cite: 1].

  • Reset State: The register bits initialize to 1'b0 strictly on hardware Power-On Reset (POR)[cite: 1].

Q205 Crypto DV SHA-256
Hardware SHA-256 Engine Architecture & Pipeline Flow
▼

A hardware SHA-256 engine processes streaming data across 5 distinct hardware stages[cite: 1]:

  • Message Ingestion: Ingests 512-bit message blocks via DMA or AXI bus[cite: 1].
  • Padding Logic: Appends a mandatory 1'b1, followed by $k$ zero bits, and finally the 64-bit message length integer to guarantee the final block is an exact multiple of 512 bits.
  • Message Scheduler: Expands sixteen 32-bit input words ($W_0 \dots W_{15}$) into sixty-four words ($W_0 \dots W_{63}$).
  • Compression Engine: Executes 64 rounds of non-linear transformations across eight 32-bit working variables ($A \dots H$) using Round Constants $K_t$.
  • Digest Accumulation: Adds working variables to the Initialization Vector (IV) to produce the final 256-bit hash[cite: 1].
Q206 Crypto DV SHA-256
Single-Block vs. Multi-Block SHA Processing Verification
▼

Single-Block Verification (< 512 bits): Verifies autonomous padding logic, IV initialization, 64-round transformation, and final digest register update[cite: 1].

Multi-Block Verification (≥ 512 bits): Verifies context accumulation across consecutive blocks[cite: 1]. The intermediate hash output of block $N$ serves as the input IV for block $N+1$[cite: 1]. Verification must ensure round counters reset to 0 between blocks without clearing working state variables.

Q207 Context Switch SHA-256
Verifying SHA Pause/Resume Context Switching
▼

Operating systems frequently interrupt low-priority background hashing to compute urgent high-priority network packet digests[cite: 1].

  • Pause Step: Assert pause mid-computation (e.g., round 32 of block 2)[cite: 1]. Ensure the engine freezes the message scheduler, completes the current round, saves working variables ($A \dots H$) into shadow registers, and asserts idle status[cite: 1].
  • Resume Step: Restore context registers, assert resume, and verify execution continues at round 33[cite: 1]. The output digest must match an uninterrupted reference run bit-for-bit[cite: 1].
